Corrections from a review of v1.0.0. Two of these matter enough to upgrade
for on their own.

## Before you upgrade

**Everyone will be signed out once.** Session ids are now derived from
`SESSION_SECRET` rather than being a plain hash, so ids issued under the old
scheme no longer match. Nothing is lost — sign in again and carry on. This is
also what makes rotating the secret actually revoke access, which the README
has always said it does and which was not true before.

Snapshot the dataset first, as with any upgrade.

## Fixed

**Settling up cleared only one direction of a netted debt.** The balances page
nets a pair into one figure, but settling cleared only the leg the arrow
pointed at. With one person owing $60 and the other $25, the page showed a
single debt of $35; settling it left the reverse $25 alive, so the person who
had just handed over $35 was then told they were owed money. Both directions
are now cleared together and the confirmation reports the net.

**`docker compose up` would not start on the documented quickstart.** Compose
turns a blank `.env` line into an empty string rather than omitting the
variable, which the configuration schema rejected, and the documented default
for `MAIL_FROM` was itself invalid. Following the README exactly produced a
container that crash-looped. A blank line now reads as "unset" for every
optional setting, and CI starts the container and waits for it to answer
before a change can land.

**A failed email suppressed itself permanently.** A relay down for five
minutes silently lost new-bill and due-soon notices for good. A failed attempt
no longer consumes its slot, and the scheduler retries recent ones — bounded,
so a relay that is down for a week is not retried for a week.

**A recurring bill that failed to issue was skipped forever.** The generator
stepped past any occurrence it could not create, so that month's rent simply
never appeared and nobody was told. It now stops at the failure and retries on
the next run.

**No way back in after a forgotten password.** The setup page closes for good
once anybody exists, so a sole admin had no recovery but editing the database
by hand. There is now an operator command:
`docker exec -it roomiebudget node scripts/set-password.mjs you@example.com`

## Changed

**Who can do what is now enforced, not just hidden.** Pausing or deleting a
recurring bill is for whoever set it up or an admin; voiding a bill is for
whoever entered it, whoever paid it, or an admin. Settling a share is
unchanged — either party, by design.

**Signing in lasts a fixed thirty days** from when you signed in. It never
renewed with use; the code implied otherwise and the comment said so outright.

**The login limit no longer lets one housemate lock another out.** It counts
attempts per account *and* per source, with a separate ceiling on how many
accounts one source may work through. Changing your password is throttled the
same way, which it was not at all before.

**CSV exports write dates as YYYY-MM-DD.** A spreadsheet in a US locale read
the previous format as either 3 October or 10 March with nothing to settle it.
The interface still shows DD/MM/YYYY.

**The startup banner reports the timezone actually in effect** and warns when
that differs from the configured one, rather than printing the configured
value regardless.
